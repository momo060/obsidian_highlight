# 绿色自然森系背景计划

## 目标

为 Obsidian 创建一个可选的“绿色自然森系”外观：整体保持清晰易读，背景带有低透明度的自然感，而不是让图片或颜色妨碍笔记阅读。

这项工作与 `Highlight Palette` 高亮插件分开维护：

- **高亮插件**：修改笔记内容，例如给选中文本添加颜色。
- **CSS snippet / 主题**：只修改 Obsidian 的外观，不修改任何笔记内容。

第一阶段推荐先交付 **CSS snippet**。它安装和关闭都很简单，随时可恢复到默认主题；当视觉语言成熟后，再考虑整理为可独立发布的 Obsidian 主题。

## 用户体验原则

1. 笔记正文的对比度优先于装饰效果。
2. 背景素材透明且低调，不能影响长文阅读。
3. 浅色模式与深色模式分别设计，不能只靠一个绿色覆盖全部界面。
4. 不修改笔记文件；禁用 snippet 后外观应立即恢复。
5. 不从网络加载背景图片，所有资源保存在本地，避免隐私、离线和加载问题。
6. 每个版本都能独立启用、验证和回退。

## 交付形式与目录

初版建议放到测试 vault：

```text
<测试 vault>/.obsidian/snippets/
└── forest-glass.css
```

当设计稳定后，再在本仓库中使用：

```text
theme/
├── manifest.json
├── theme.css
└── assets/
    └── forest-texture.png       # 可选；本地、低对比度纹理
```

`forest-glass.css` 是开发版；`theme/` 是将来发布为独立主题时的结构。两者不要同时启用，以免样式叠加造成难以排查的问题。

## 分阶段计划

### 阶段 0：确定视觉方向

先明确以下设计决定：

- 主色：偏苔藓绿、鼠尾草绿，还是偏深林绿？
- 默认模式：浅色、深色，或两者都支持？
- 装饰强度：仅柔和渐变，还是增加叶片/森林纹理？
- 窗口透明度：只让侧边栏半透明，还是让编辑区也略透明？
- 字体与图标：保持 Obsidian 默认，还是同时更换？

**验收标准**：选定 3–5 个色值和一张视觉参考图；不开始写 CSS 前先确定方向。

### 阶段 1：无图片的安全 MVP

创建 `forest-glass.css`，只使用 CSS 变量、渐变和半透明色块，不引入图片资源。

范围：

- 应用主背景、侧栏、文件浏览器和状态栏的绿色层次。
- 编辑器/阅读视图保留接近白色或深灰的高对比阅读底色。
- 为链接、按钮、激活标签页和选中文本定义一致的绿色强调色。
- 设置 hover、active、focus 状态，保证交互状态能分辨。
- 同时处理浅色与深色模式。

**验收标准**：在一篇长笔记中阅读舒适；文件名、链接、代码块、引用和选中文本均清晰可辨；关闭 snippet 后恢复默认外观。

### 阶段 2：玻璃质感与自然层次

在阶段 1 的颜色系统稳定后，加入谨慎的玻璃效果。

范围：

- 对侧栏和浮动面板使用低透明背景。
- 在支持的桌面环境中使用轻微 `backdrop-filter: blur(...)`；同时提供无模糊的后备样式。
- 用极弱的径向/线性渐变模拟阳光穿过树叶的层次。
- 不对正文文字区域使用过强透明度或模糊。

**验收标准**：菜单、设置窗口、弹窗与多个分栏打开时仍能清楚区分；没有明显卡顿；正文仍为阅读焦点。

### 阶段 3：可选本地森林纹理

只有在不使用图片的版本已经满意时，才添加纹理。

范围：

- 使用自己拥有版权、可再发布的图片或自行生成的纹理。
- 将图片压缩为适合界面的尺寸，使用 PNG/WebP；避免大尺寸照片。
- 图片只放在窗口边缘、侧栏或标题背景，不放在正文底下。
- 在 CSS 中叠加半透明色层，确保图片不抢眼。
- 提供“纯色版”与“纹理版”两个独立 snippet，用户只启用其中一个。

**验收标准**：离线可用；冷启动不明显变慢；在浅色和深色模式中均不过曝或发灰。

### 阶段 4：扩展界面细节

在核心界面稳定后，逐项补充：

- 标签页、分栏标题和标题栏。
- 搜索结果、反向链接、标签、Properties。
- 表格、代码块、callout、任务列表、引用块。
- 日历、图谱、设置页等核心插件界面。
- 社区插件界面：只在实际使用该插件时按需适配，避免猜测其内部类名。

**验收标准**：每补一类界面，就在浅/深色模式下手动测试；发现影响可读性的选择器时及时缩小作用范围。

### 阶段 5：整理为独立主题（可选）

当 snippet 被长期使用且设计稳定后，才创建主题仓库或仓库内 `theme/` 目录。

范围：

- 编写主题名称、版本、作者和说明。
- 写 README：截图、安装方式、支持范围、已知限制。
- 整理本地素材的许可来源与许可证。
- 按 Obsidian 主题提交要求验证 manifest 和 CSS。

**验收标准**：新用户只需安装主题即可获得完整外观，不依赖高亮插件或你的本地 vault 设置。

## 每次修改的测试清单

- 在 **浅色模式** 和 **深色模式** 下检查。
- 打开长笔记、代码块、表格、callout、链接和任务列表。
- 打开设置页面、命令面板、右键菜单和弹窗。
- 将窗口缩窄，并使用至少两个分栏。
- 关闭 snippet，确认可完整恢复默认外观。
- 确认 CSS 没有修改 Markdown 文件或 `.obsidian` 以外的数据。

## 风险与应对

| 风险 | 应对 |
| --- | --- |
| 绿色太多导致正文难读 | 正文背景保持中性；绿色只作为层次与强调色。 |
| 半透明导致文字和背景混在一起 | 限制半透明区域为侧栏/弹窗；正文使用实色底。 |
| Obsidian 更新后类名变化 | 使用官方 CSS 变量和稳定容器优先；每次升级后回归测试。 |
| 图片影响性能或版权不清 | 默认不用图片；只使用本地、已授权、压缩过的素材。 |
| 与其他主题/snippet 冲突 | 独立文件、清晰命名、一次只启用一个相关 snippet。 |

## 第一版建议

从“**浅色鼠尾草绿 + 深色森林绿 + 无图片 + 轻微玻璃侧栏**”开始。

这是风险最低、最容易验证，也最适合学习 CSS 的版本。完成后再决定是否加入可选的本地森林纹理。
