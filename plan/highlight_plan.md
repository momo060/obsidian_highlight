# Highlight Palette：颜色功能优化计划

## 目标

把当前“在命令面板中选择一种固定颜色”的原型，逐步做成一个可靠、易用的高亮工具：

- 选中文字后能快速着色，不必每次都使用 `⌘ + P`。
- 可以从色盘选择任意颜色。
- 常用颜色可以保存，重启 Obsidian 后仍可使用。
- 所有颜色信息直接写入 Markdown 笔记，脱离插件后文字内容仍然存在。

本计划只处理**文字高亮颜色**，不处理 Obsidian 的整体主题、背景或窗口外观。

## 现有实现

当前插件已经提供五个命令：黄色、绿色、粉色、蓝色、紫色。

执行命令时，插件将选中文字替换为类似以下的 Markdown/HTML：

```html
<mark style="background-color: #fff3a3;">选中的文字</mark>
```

这个格式的优点是颜色随笔记保存；缺点是用户必须从命令面板找到命令，且目前不能选任意颜色。

## 产品决定（先采用）

### 颜色保存格式

继续使用 `<mark style="background-color: #RRGGBB;">文字</mark>`。

原因：

- 单段文字可以拥有各自独立的颜色。
- 不依赖某个主题预先定义颜色名称。
- 直接打开 Markdown 文件仍能看懂其含义。

限制：源代码模式会显示 HTML 标签；这是为了保存每段文字的独立颜色而做出的取舍。

### 交互优先级

按以下顺序实现：

1. 命令面板保留，作为始终可用的键盘入口。
2. 编辑器右键菜单增加 **Highlight color** 子菜单，作为第一个免命令面板入口。
3. 选中文字时显示小型浮动调色板，作为后续更直接的入口。

不尝试修改 macOS 顶部的原生 **Format** 菜单。它不是稳定的公开插件扩展点；强行接入会造成桌面端兼容性和后续维护风险。

## 阶段 1：整理现有高亮核心

### 要做什么

- 将“替换选中文字”“生成 `<mark>` 标签”“HTML 转义”保留在独立模块中。
- 为预设颜色建立统一的数据结构，避免命令、右键菜单和色盘各自维护一份颜色列表。
- 添加一个“移除高亮颜色”的命令。
- 对空选区、跨段落选区、已经着色的文字，给出明确而安全的行为。

### 验收方式

- 五种预设颜色仍能使用。
- 没有选择文字时不改动笔记，并显示提示。
- `npm run build` 通过。
- 在 Live Preview 和阅读视图中验证颜色显示。

### 需要先决定的细节

- 再次应用颜色时：先简单地嵌套 `<mark>`，还是识别并替换已有颜色？

建议：第一版实现“识别同一次选择范围内的已有 `<mark>`，替换颜色而非无限嵌套”。

## 阶段 2：自定义色盘与常用颜色

### 要做什么

- 新增命令 **Choose custom highlight color**。
- 打开一个小弹窗，内含浏览器原生颜色选择器（色盘）和十六进制颜色输入框。
- 点击“应用”后，将当前颜色应用到选中文字。
- 将最近使用的颜色保存为常用颜色；初始保留五个默认色。
- 在插件设置页提供“管理常用颜色”：添加、删除、恢复默认色。

### 数据保存方式

使用 Obsidian 的 `loadData()` / `saveData()` 保存插件设置。它会产生插件私有的 `data.json`，位于 vault 的插件目录中。

`data.json` 是个人偏好，不提交到 GitHub；每个使用者都有自己的颜色列表。

### 验收方式

- 能从色盘选择一个非预设颜色，例如 `#F97316`。
- 关闭再打开 Obsidian 后，该颜色仍出现在常用颜色中。
- 无效的十六进制输入无法应用，并给出清晰提示。

## 阶段 3：右键菜单入口

### 要做什么

- 在 Markdown 编辑器的右键菜单中新增 **Highlight color**。
- 其下显示预设/最近使用的颜色与 **Choose custom color…**。
- 只有编辑器中存在选区时才显示或启用颜色操作。

### 为什么先做它

- 使用 Obsidian 的公开菜单 API，稳定、维护成本低。
- 不需要自行计算浮动面板位置。
- 对鼠标操作用户比命令面板更直观。

### 验收方式

- 选中文字后右键，可以从菜单直接上色。
- 不选文字时，菜单不会错误修改内容。
- 命令面板入口仍正常工作。

## 阶段 4：选区浮动调色板（增强体验）

### 要做什么

- 在编辑器内选中文字后，在选区附近显示一个小工具栏。
- 工具栏显示常用颜色、更多颜色按钮、取消/移除颜色按钮。
- 点击颜色后立即应用，并自动关闭工具栏。
- 用户按 Escape、取消选择、切换笔记或停用插件时，工具栏必须正确消失。

### 技术说明

该功能需要与 Obsidian 使用的 CodeMirror 编辑器协作，监听选区变化并计算工具栏位置。因此比右键菜单复杂，必须重点测试。

### 验收方式

- 键盘选区和鼠标选区都能出现工具栏。
- 工具栏不会遮挡输入或遗留在其他笔记中。
- 连续应用多种颜色不会损坏 Markdown。
- 在窄窗口和不同缩放比例下位置可用。

## 阶段 5：质量与发布准备

### 要做什么

- 移除官方 sample 的骰子图标、演示弹窗、示例设置、全局点击提示和定时器。
- 将插件改名为自己的名称和唯一 ID，并使文件夹名称与 ID 一致。
- 将现有的英文提示统一为简洁、可本地化的文案。
- 写 README：安装、使用、颜色格式、已知限制、隐私说明。
- 更新 `.gitignore`，确保不提交 `node_modules/`、`data.json`、`.DS_Store` 和生成文件。
- 运行 `npm run build` 和 `npm run lint`；解决不再需要的 sample lint 错误。

## 推荐实施顺序

```text
阶段 1（稳定核心）
        ↓
阶段 2（色盘 + 保存预设）
        ↓
阶段 3（右键菜单）
        ↓
阶段 4（浮动工具栏）
        ↓
阶段 5（清理 + GitHub 发布）
```

每完成一个阶段，都先在测试 vault 中手动验证，再提交一次 Git。这会让每次改动都容易回退和理解。
